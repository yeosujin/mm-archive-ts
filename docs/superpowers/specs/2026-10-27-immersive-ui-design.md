# 몰입형 UI 개편 설계 (v2.0.0)

- 작성일: 2026-10-27
- 상태: 설계 확정, 구현 전
- 목업: `.superpowers/brainstorm/66139-1793057944/content/prototype.html` (실제 데이터 기반 통합 프로토타입, git 미추적)

## 1. 배경과 목표

지금 mmemory는 "검색해서 찾는 사이트"로 보인다. 홈은 검색바 + 그 해 오늘 + PICK이고, 나머지는 도메인별 목록 페이지다.

목표는 **찾지 않아도 둘러보게 되는 앱**이다. 두 가지 문법을 쓴다.

- **고를 때는 OTT** — 모먼트 탭 표지를 연도·월 레일로
- **볼 때는 숏폼/스토리** — 모먼트는 위아래 숏폼, 그 해 오늘은 좌우 스토리

포스트·사진·에피소드 탭 화면, 검색, 캘린더 화면은 이번 범위가 아니다(§9).

## 4. 1단계 — 미디어 인프라

### 4.1 CDN 캐시 규칙 (A)

Cloudflare 대시보드에서 **사용자가 직접** 설정한다(코드 변경 없음).

- 대상: `cdn.mmemory.cloud` 전체
- Cache Rule: Cache eligibility = Eligible for cache, Edge TTL = 1개월 이상, Browser TTL = 1일 이상
- R2 객체는 같은 키로 덮어쓰지 않는 것을 전제로 한다(트랜스코딩은 새 키에 쓴다, §4.3)

### 4.2 r2.dev URL 정리 (B)

`pub-e283cbe5050744f68f0725eaa678e156.r2.dev` 로 시작하는 URL을 `cdn.mmemory.cloud`로 바꾼다.

- 대상 컬럼: `moments.tweet_url`, `moments.thumbnail_url`, `photos.image_url`, `photos.thumbnail_url`, `posts.media[].url/thumbnail`, `episodes.messages[].content`(image), `episodes.tweet_images[]`
- 키 경로는 그대로, 호스트만 치환
- SQL 파일로 작성(`supabase/sql/`), **운영 DB 실행 전 사용자 확인**
- 로컬 `.env`의 `VITE_R2_PUBLIC_URL`은 이미 cdn 도메인이다. r2.dev URL이 계속 생기지 않도록 **Vercel 운영 환경변수 값도 확인**한다

### 4.3 트랜스코딩 (D)

**변환 규격**

| 항목 | 값 |
|---|---|
| 컨테이너/코덱 | mp4, H.264 (high), AAC 128k |
| 해상도 | 긴 변 최대 1280px, 비율 유지, 확대하지 않음 |
| 프레임 | 최대 30fps |
| 비트레이트 | 최대 약 2.5Mbps |
| 기타 | `-movflags +faststart` |

이미 규격 이하인 파일(예: 1080p 24fps 2.3Mbps)도 컨테이너 통일을 위해 변환한다. 원본보다 커지면 원본을 그대로 쓴다.

**저장 방식**

- 변환본은 **새 키**에 쓴다: `videos/t/{원본키 basename}.mp4`
- 원본 객체는 **원래 키 그대로 둔다** — 기존 URL이 계속 열리고, 캐시 무효화도 필요 없다
- DB: `moments`에 `original_url text null` 컬럼 추가. 변환 시 `original_url ← 기존 tweet_url`, `tweet_url ← 변환본 URL`
- `original_url`이 채워진 행 = 변환 완료 (멱등 판정 기준)
- 포스트 영상: `posts.media[]` 항목에 `original_url` 필드를 추가하는 방식으로 동일 처리

**썸네일 동시 생성**

변환하면서 `thumbnail_url`이 비어 있으면 0.5초 지점 프레임을 jpg로 뽑아 올리고 채운다. 비어 있는 모먼트 썸네일(최근 9개 중 5개 등)이 함께 해결된다.

**기존 데이터 일괄 처리**

- `scripts/transcode-r2-videos.ts` — 기존 `scripts/remux-r2-videos.ts` 구조를 따른다(`--dry-run`, `--limit`, 멱등)
- DB에서 대상을 고른다(R2 목록이 아니라 `original_url is null`인 행)
- 로컬 맥에서 실행, 하드웨어 인코딩(`h264_videotoolbox`) 사용 가능하면 사용
- 1,414개 + 포스트 영상, 예상 결과 용량 약 4GB

**신규 업로드 자동화**

- `.github/workflows/transcode.yml` — 일정 주기(예: 1시간)로 같은 스크립트를 실행
- 러너에 ffmpeg 설치, R2·Supabase 자격증명은 Actions secrets
- 어드민 업로드 화면은 바꾸지 않는다. 업로드 직후 잠시 원본이 재생되고, 다음 실행 때 변환본으로 바뀐다

**비용** — 저장 약 16.4GB(원본) + 4GB(변환본), R2 전송비 없음. 월 $0.2 내외.

### 4.4 1단계 완료 기준

- 모먼트·포스트 영상 `tweet_url`/`url`이 전부 cdn 도메인의 mp4
- 샘플 10개 `cf-cache-status`가 두 번째 요청부터 `HIT`
- 썸네일 빈 모먼트 0개
- 기존 화면(홈 영상, 모먼트 아코디언, 포스트 모달) 재생 정상

## 5. 2단계 — 영상 썸네일

`videos.thumbnail_url`이 전부 비어 있다. OTT 표지와 상세 화면이 썸네일에 의존한다.

| 플랫폼 | 방식 | 저장 |
|---|---|---|
| YouTube (263) | URL에서 영상 ID 추출 → `https://i.ytimg.com/vi/{id}/hqdefault.jpg` | **저장 안 함**, 렌더 시 계산 |
| Weverse (58, 전부 모먼트 있음) | 기본은 첫 모먼트 썸네일. 공식 썸네일은 어드민이 **북마클릿**으로 채움 → R2 복사 → `thumbnail_url` | 채운 것만 저장 |
| Instagram·기타 (11) | 첫 모먼트 썸네일, 모먼트도 없으면 플랫폼 색 블록 | 저장 안 함 |

표시 우선순위 헬퍼 `getVideoCover(video, moments)`: `thumbnail_url` → YouTube 계산 → 첫 모먼트 썸네일 → 없음(null).

### 5.1 위버스 공식 썸네일 — 서버 자동 수집을 하지 않는 이유

위버스 라이브 페이지는 일반 요청에 빈 SPA 껍데기만 준다(og:image 없음, 2026-10-27 확인). og 태그는 링크 미리보기 봇에게만 내려 준다. 서버가 봇 User-Agent를 흉내 내거나 비공개 API 서명을 흉내 내는 방식은 접근 제한 우회라 쓰지 않는다. 앱은 이미지 길게 눌러 복사도 막혀 있다.

### 5.2 북마클릿 흐름 (PC 브라우저)

1. 어드민 `/admin/covers` — 표지(`thumbnail_url`)가 없는 위버스 영상 목록. 각 줄에 위버스 링크와 현재 대체 표지(첫 모먼트) 미리보기. 상단에 북마클릿 버튼(북마크바로 끌어다 설치)
2. 링크로 위버스 라이브를 열고 북마클릿을 누르면, **사용자가 보고 있는 화면**에서 썸네일 주소를 읽는다 — 광고가 끝난 뒤 플레이어 배경 이미지(`video-phinf.pstatic.net`) → `og:image` → `data:`가 아닌 `video[poster]`. 추천 목록 `<img>`(`phinf.wevpstatic.net`)는 쓰지 않는다
3. 북마클릿은 `{어드민 origin}/admin/covers?url={라이브 주소}&image={썸네일 주소}`를 새 탭으로 연다
4. 그 페이지가 라이브 주소로 영상을 찾고, `/api/r2`의 `import` 액션으로 이미지를 서버에서 받아 R2 `covers/{videoId}-{시각}.jpg`에 올린 뒤 `thumbnail_url`을 갱신한다. "저장됨"과 다음 대상 링크를 보여 준다
5. `import`는 `pstatic.net`·`wevpstatic.net` 호스트 이미지만 받는다(SSRF 방지), 이미지 타입·10MB 이하만

새 탭마다 다시 로그인하지 않도록 어드민 비밀번호 보관을 `sessionStorage` → `localStorage`로 바꾼다(관리자 개인 PC 전제, 로그아웃 시 삭제).

PC 크롬에서 확인(2026-10-28): 광고 중에는 없고, 광고가 끝나면 플레이어 배경으로 뜬다.

- 상단 **글자 탭**(아이콘 없음): 홈 · 모먼트(`/videos`) · 포스트 · 사진 · 에피소드
- 헤더 오른쪽: ⌕ 검색(`/search`), 📅 캘린더(`/calendar`)

- 숏폼·스토리 뷰어가 열리면 헤더·탭은 가려진다(전체 화면 오버레이)
- 라우트는 바꾸지 않는다

## 7. 4단계 — 모먼트 탭

### 7.1 표지 (`/videos`)

```
[2026] 2025  2024  2023          ← 연도 탭 (기본: 가장 최근 연도)
(전체)(위버스 라이브)(아일릿 채널)(외부 출연)
  └ 위버스 라이브 선택 시: (전체)(🤍 둘만)(💙 모카)(🩵 민주)(🖤 여러명)
┌ 히어로 ────────────────┐
│ 2025.04.03 · 위버스 라이브 │
│ 오끼까페 오픈              │
│ 모먼트 40  [▶ 넘겨보기]    │
└────────────────────────┘
10월 ─ [카드][카드][카드] →     ← 월별 가로 레일
9월  ─ [카드][카드] →
```

**분류 칩** — 틀릴 수 없는 기준만 쓴다.

| 칩 | 판정 |
|---|---|
| 위버스 라이브 | URL이 weverse |
| 아일릿 채널 | URL이 YouTube이고 `channel_name === 'ILLIT'` |
| 외부 출연 | 그 외 전부 (YouTube 타 채널, Instagram, X, 기타) |

기존 `YOUTUBE_CATEGORIES` 제목 패턴 분류(비하인드·슈일릿 등)는 표지에서 쓰지 않는다. 공식 채널 46개가 어떤 패턴에도 안 잡히는 문제가 있었다.

**히어로**

- 후보: 현재 연도·칩 조건에서 **모먼트가 있는 영상** 중 랜덤
- 연도·칩을 바꾸면 다시 뽑는다
- 표지 이미지(`getVideoCover`)를 먼저 보여주고 **1초 뒤 첫 모먼트를 음소거로 앞 8초만 재생**, 끝나면 표지로 페이드 백
- 화면 밖으로 나가면 정지. `prefers-reduced-motion` 또는 `navigator.connection.saveData`면 재생하지 않음
- 소리 버튼 없음(항상 음소거)
- 탭 → 그 영상의 첫 모먼트부터 숏폼 뷰어
- 후보가 없으면 히어로 숨김

**월별 레일**

- 월 내림차순, 레일 안도 날짜 내림차순
- 칩 결과가 0개인 월은 숨김
- 카드: 16:9 표지 + 제목 2줄 + `MM.DD`
  - 모먼트 있음: 배지 `모먼트 N` → 탭하면 영상 상세
  - 모먼트 없음: 배지 `보러가기` → 탭하면 원본 URL 새 탭
  - 출처 태그: 위버스는 `{아이콘} LIVE`, 외부 출연은 채널명
- 모먼트 없는 영상(119개)도 레일에 포함한다. 기존 '전체 보기' 그리드는 두지 않는다

### 7.2 영상 상세

- 라우트: `/videos/:id` (신규). 표지 카드에서 진입, 뒤로가기로 표지 복귀
- 상단: 표지 16:9, 제목, `날짜 · 분류 · 모먼트 N`, 버튼 `▶ 모먼트 재생`(첫 모먼트부터) · `보러가기 →`(원본 새 탭)
- 모먼트: **3열 세로(3:4) 그리드, 제목 없음**. 탭 → 그 모먼트부터 숏폼 뷰어
- 정렬: `position` 오름차순 → `created_at` 오름차순 (기존 `getMoments` 순서)

### 7.3 숏폼 뷰어 (모먼트 전용)

| 요소 | 동작 |
|---|---|
| 넘기기 | **위아래 스와이프**(scroll-snap), 한 장씩 |
| 재생 | 화면에 들어온 장만 재생, 나머지 정지. 끝나면 다음 장으로 자동 스크롤 |
| 소리 | **켜고 시작**. 브라우저가 막으면 음소거로 재생하고 🔇 표시 |
| 탭 | 일시정지/재생 |
| 상단 | ✕ 닫기, `n / N` — **진행 막대 없음** |
| 오른쪽 | 🔊 소리 토글, ⤓ 저장 (기존 `VideoPlayer` 기능: 휴대폰은 공유 시트, PC는 다운로드) |
| 하단 | **틱톡식 재생바**: 평소 얇게, 누르면 두꺼워지며 드래그로 탐색, 드래그 중 `0:12 / 0:48` 표시 |
| 제목 | **표시하지 않음** |
| 보러가기 | 없음 (상세 화면에 있음) |
| 닫기 | ✕, **첫 장에서 아래로 당김**, **마지막 장에서 위로 넘김** |
| 마지막 장 | 끝나면 그 자리에서 정지 (자동으로 닫지 않음) |
| 안내 | 기기에서 처음 열 때만 첫 장 하단에 `︿ 위로 넘겨 다음`. 넘기면 사라지고 `localStorage`에 기록 |
| 배치 | 세로·가로 영상 모두 `object-fit: contain`, 뒤에 같은 썸네일 흐림 배경 |

소리 상태는 뷰어를 닫아도 세션 동안 유지한다.

### 7.4 로딩 전략 (모먼트·스토리 공통)

1단계 트랜스코딩과 별개로, 체감 대기를 줄인다.

- **썸네일 즉시 표시**: 영상 `poster`로 썸네일, 0.3초가 넘을 때만 로딩 표시
- **누르기 전에 받기**: 상세 그리드·홈 그리드 칸에 `pointerdown` 시점부터 해당 영상 `preload`
- **미리보기 이어받기**: 히어로/홈 카드가 이미 받고 있던 영상을 뷰어 첫 장에서 재사용(같은 URL이면 브라우저 캐시 활용)
- **다음 장 미리 받기**: 현재 장 다음 1개를 `preload="auto"`. 데이터 절약 모드면 하지 않음

## 8. 5단계 — 그 해 오늘

### 8.1 홈 (`/`)

```
[2026년 오늘][2025년…  ← 연도별 카드, 옆으로 넘김 (옆 카드 살짝 보임)
   • ○ ○ ○               ← 점 (2개 연도 이상일 때)
⌕ 느낌·상황으로 찾아보세요   [AI]
새로 올라온 모먼트          모먼트 탭 ›
[ ][ ][ ]                ← 3열 그리드, 9개
[ ][ ][ ]
[ ][ ][ ]
궁금한 점이나 요청 남기러 가기 →
```

**연도별 카드**

- 해당 날짜 콘텐츠가 있는 연도마다 카드 1장, 최신 연도 먼저
- 카드: 3:4, 그 해 첫 장면 이미지, `YYYY년 오늘`, `N년 전 · M개`(올해면 `올해`), `▶ 넘겨보기`. 첫 카드에만 `그 해 오늘 · M월 D일`
- **보이는 카드만** 첫 장면이 영상이면 음소거 반복 미리보기
- 탭 → **그 해부터** 스토리 시작
- 한 해뿐이면 카드 1장, 점 없음

**그 해 오늘이 없는 날**

- 그 해 오늘이 있는 날(239일) 중 하나를 **날짜 시드로 고정 랜덤** 선택 — 하루 동안 같은 날
- 첫 카드 문구: `오늘은 기록이 없어요 · 대신 M월 D일`
- 이 날은 자동 스토리를 띄우지 않는다

**새로 올라온 모먼트**: `created_at` 최신 9개. 탭 → 그 9개로 숏폼 뷰어(§7.3).

**제거**: `mmemory` 타이틀·부제 히어로, 메뉴 칩 줄, PICK 폴백 렌더링.

### 8.2 자동 스토리

- 그 해 오늘이 있는 날, **기기에서 그날 처음 홈에 들어오면** 스토리를 자동으로 연다
- 판정: `localStorage`에 마지막 자동 표시 날짜(`YYYY-MM-DD`) 저장
- 자동으로 열릴 때는 사용자 제스처가 없으므로 음소거로 시작한다(브라우저 정책)
- 닫으면 홈. 다시 보기는 홈 연도 카드

### 8.3 스토리 뷰어

**구성 (프레임)**

같은 해 안의 순서: 영상별 모먼트 묶음 → 모먼트 없는 영상 → 사진 → 포스트 → 에피소드. 연도는 최신부터.

| 타입 | 프레임 | 표시 | 길이 |
|---|---|---|---|
| 모먼트 | 1개 | 영상만, 제목 없음. 오른쪽 🔊 ⤓ | 영상 길이 |
| 모먼트 없는 영상 | 1개 | 표지 + 제목 + `보러가기 →` | 5초 |
| 사진 (같은 제목 묶음) | **장마다 1개** | 사진 + 제목(접미사 `-1` 제거) | 5초 |
| 포스트 | **미디어마다 1개** (없으면 본문 1개) | 미디어 + `{플랫폼} 에서 보기 ↗` 칩 + 본문 2줄 + `더보기`(바텀시트로 전문) | 사진 5초 / 영상 길이 |
| 에피소드 | 1개 | 채팅 말풍선 화면(DM·댓글·리스닝파티), 이미지 메시지 포함 | `3초 + 0.7초 × 메시지 수`, 최대 20초 |

사진·포스트에는 저장·소리 버튼이 없다. 포스트 영상은 뷰어 소리 상태를 따른다.

**조작**

| 동작 | 결과 |
|---|---|
| 화면 오른쪽 2/3 탭 | 다음 프레임 |
| 왼쪽 1/3 탭 | 이전 프레임 |
| 좌우 스와이프 | 다음 해 / 이전 해 첫 프레임 |
| 길게 누르기 (250ms+) | 멈춤, 떼면 이어서 |
| 아래로 쓸어내리기 | 닫기 (손가락 따라 내려감) |
| ✕ | 닫기 |
| 마지막 해 마지막 프레임이 끝남 | 닫기 |

**표시**

- 상단 진행 막대: **현재 해의 프레임 수만큼**, 시간에 따라 차오름
- 상단 라벨: `YYYY년 오늘 · N년 전` — 해가 바뀔 때 가운데 큰 연도 표시는 **하지 않는다**
- 상단 오른쪽: 🔊(영상 프레임일 때), ✕
- 하단 재생바 없음
- 기기에서 처음 열 때 안내: `탭하면 다음 · 옆으로 넘기면 다른 해 · 아래로 쓸면 닫기`

**판정 규칙**: 기존 `filterOnThisDay`(월/일 비교, 모먼트는 상위 영상 날짜)를 그대로 쓴다 → `knowledge-vault/wiki/concepts/on-this-day.md`. X 봇과 같은 규칙이 유지돼야 한다.
