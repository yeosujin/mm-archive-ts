# Search (검색)

## 한 줄 정의

키워드 검색과 AI 의미 검색이 **한 화면에 모드 토글로** 공존한다.

## 위치

- 라우트: `/search`, 네비에는 아이콘으로 노출
- 공개 페이지: `src/pages/Search.tsx`
- 클라이언트 래퍼: `src/lib/semanticSearch.ts`
- Edge Function: `supabase/functions/semantic-search/`

## 두 모드

| | 키워드 모드 (기본) | AI 모드 |
|---|---|---|
| 방식 | 캐시된 전체 데이터를 클라이언트에서 문자열 매칭 | 임베딩 벡터 유사도 |
| 네트워크 | 없음 | Edge Function 호출 |
| 하이라이트 | 일치 지점 표시 | 글자가 맞는 결과만 표시 |
| 비용 | 0 | [[google-gemini]] 임베딩 쿼터 소모 |

AI 모드는 **명시적으로 켰을 때만** 호출한다. 기본 모드에서 쿼터를 쓰지 않기 위한 설계다 → [[embedding-semantic-search]]

## 화면 (2.2.0)

- 검색창은 **헤더 첫 줄**에 있다: 검색 화면에서는 로고 줄 대신 `← [검색어  ✨AI]`. `Layout`이 첫 줄을 빈 칸(`searchSlot`, Outlet context)으로 두고 `Search`가 거기에 포털로 띄운다. ←는 앱 안에서 왔으면 뒤로, 링크로 바로 들어왔으면 홈
- 검색 화면은 어느 탭에도 속하지 않아 **탭 줄을 숨긴다**. 대신 검색어가 없거나 입력창을 비우면 '둘러보기' 바로가기(모먼트·포스트·사진·에피소드·캘린더), 칩으로 한 종류를 고르면 결과 끝에 `○○ 탭에서 전체 보기 ›` (영상·모먼트는 모먼트 탭, 검색어는 넘기지 않음)
- 검색 입구는 헤더 오른쪽 돋보기 하나(홈 본문 검색창은 없앰). 누르면 검색 화면으로. iOS는 화면이 바뀐 뒤의 focus()로 키보드를 띄우지 않아서, 누르는 순간 `Layout`의 숨은 입력칸(`.kb-proxy`)에 focus해 키보드를 띄우고 검색 입력창(autoFocus)이 이어받는다
- 결과 위에 `‘검색어’ N건`
- 종류 칩(`mc-chip`): 전체 · 영상 · 모먼트 · 포스트 · 에피소드, 결과 있는 종류만, 옆에 개수
- 결과는 **한 그리드에 섞어서** 보여 준다 (모바일 2열, 768px 3열, 1024px 4열). 카드는 캘린더와 같은 `VideoCard` / `EntryCard`, 아래 줄에 `종류 · 날짜`
- 순서: 키워드 모드는 최신순(같은 날은 영상 → 모먼트 → 포스트 → 에피소드). AI 모드는 **글자가 맞는 결과를 먼저**(같은 최신순) 두고, 그 뒤에 AI만 찾은 결과를 유사도 순으로 붙인다. AI는 30개 상한·점수 컷 때문에 글자가 맞는 결과도 놓칠 수 있어서다. AI 응답을 기다리는 동안·AI 오류 때도 글자가 맞는 결과는 먼저 보인다
- 누르면 그 자리 팝업: 영상 `?v=`, 모먼트 `?m=`, 포스트·에피소드 `?d=kind:id` (캘린더와 같음). 새 탭 클릭은 각 페이지로
- 모먼트 뷰어 위쪽 `영상 보기 ›`: `?m=`을 `?v=`로 바꿔 영상 상세를 연다(뒤로가면 모먼트로). `MomentViewer`의 `onOpenVideo`를 넘긴 캘린더·검색에만 보인다
- 카드 항목은 `calendarDays.ts`의 `momentEntry` · `postEntry` · `episodeEntryBuilder`로 만든다

## 유도 장치

키워드 검색 결과가 0건일 때 "AI로 다시 찾아볼까요?" CTA를 띄운다. 헛수고한 사용자만 AI 모드로 넘긴다.

## 함정

- 키워드 모드는 **캐시된 데이터만** 본다. `DataContext`의 5분 TTL 안에 들어온 새 콘텐츠는 잡히지 않는다
- AI 모드 결과는 임계값으로 잘린다. "분명 있는데 안 나온다"면 유사도가 `AI_SIM_FLOOR` 아래일 수 있다 → [[ai-search-threshold-tuning]]
